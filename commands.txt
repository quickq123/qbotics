QBOTICS: HANDY COMMANDS
Run these from this folder (g:\MinecraftMods) in a terminal.

PLAY TEST (the game, with other mods)
    gradlew :neoforge:runPlaytest

    Opens straight into the "Qbotics Playtest" world: creative, flat, cheats on.
    The first time, the world is made and the test stage is built beside you.
    After that the same world opens again, so what you build stays.
    In the game:  /qbotics stage   rebuilds the stage where you stand.
    To start the world over, delete:  neoforge\runs\playtest\saves

ADDING MORE MODS TO THE PLAY TEST
    1. Open  neoforge\playtest-mods.txt
    2. Add a line with the mod's file name, as it appears in the FTB Evolution 2 mods folder
       (C:\Users\qrick\curseforge\minecraft\Instances\FTB Evolution 2\mods),
       with * in place of the version, for example:
           ae2-*.jar
    3. Add the mods it needs as well (the game says which are missing if it won't start).
    4. Run the play test again. The mods are copied in before the game starts.

    The play test's mods folder is made to match the list each time, so a mod dropped in
    by hand is removed: always add it to the list instead.
    Mods must be for Minecraft 26.1.2 on NeoForge.
    To take mods from another pack, add this to the command:
        -Pqbotics.playtestModsFrom="C:\path\to\that\pack\mods"

IN THE GAME
    /qbotics limits          your active computers and antennas against your limits
    /qbotics limits all      everyone's (operators)
    /qbotics stage           builds the test stage where you stand (operators)

OTHER COMMANDS
    gradlew :neoforge:runGameTestServer     runs the automatic in-game tests
    gradlew build                           builds the mod (the jar is in neoforge\build\libs)
    gradlew :neoforge:runClient             the plain development game, no other mods

RELEASING A VERSION ON GITHUB
    In Git Bash (not PowerShell), from this folder:
        ./release.sh 0.2.0 --dry-run     checks, tests and builds; publishes nothing
        ./release.sh 0.2.0               the real release
        ./release.sh 0.2.0 --notes notes.md   your own text above the list of changes

    It sets mod_version, runs the game tests (any failure stops it), builds the jar,
    commits and tags it as v0.2.0-mc26.1.2, pushes, and makes the GitHub release with
    qbotics-0.2.0-mc26.1.2.jar attached. The Minecraft version comes from gradle.properties.
    Needs the GitHub CLI, once:  winget install GitHub.cli   then   gh auth login
